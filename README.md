# Nodo

Google ドキュメントの編集画面に、ページのツリーと段落の書式メニューを足す Manifest V3 拡張機能です。文書そのものは Google ドキュメントのまま、Google ドライブに保存されます。Markdown や Word への変換、別サーバーとの同期はしません。

拡張機能を無効にするか、画面上の「標準表示」を選ぶと、いつもの Google ドキュメントに戻ります。

## この版でできること

- 左のタブ一覧を、Notion のページツリーのように表示する。タブがページ、サブタブが子ページです。
- ページの切り替え、追加、名前の変更、複製、削除、上へ、下へ。同じ階層ではドラッグでも並べ替えます。
- キャレットの左、またはサイドバーの「現在の段落の書式」から、テキスト、見出し 1〜3、箇条書き、番号付きリストを選ぶ。
- メニューと書式ツールバーを隠し、必要なときだけ戻す。ページ設定（ページレスや余白）は変えません。

Notion のデータベースや全ブロックの再現は対象外です。

## 構成の判断

開いている画面のカーソル位置と、公式の Google Docs API は別物です。Docs API はタブや本文をインデックスで更新できますが、編集中のキャレットは見えません。Brave では `chrome.identity.getAuthToken` が Google から拒否されます（カスタム URI スキーム）。`launchWebAuthFlow` は Google Cloud の OAuth クライアントが必要です。どちらも、今開いている段落へ書式を当てる問題は解けません。

そのため API も認証も使っていません。Google Cloud の設定は不要です。すでに開いている編集画面の操作だけを使います。

| やりたいこと | 採用した方法 | 根拠 |
| --- | --- | --- |
| ページの表示と切り替え、追加、名前、並べ替え | 画面上のタブ一覧とタブメニューを操作する | 公式 API はカーソルを知らない。画面操作なら権限、元に戻す、共同編集はドキュメント側のまま |
| 段落の書式 | 公式ショートカットを、入力用 iframe の中のコンテンツスクリプトから編集欄へ送る | 親ページのコンテンツスクリプトは `about:blank` の中を読めない。`runtime.sendMessage` も他のフレームへ届かないので、サービスワーカーが同じタブへ転送する。`Ctrl+Alt+0`〜`3`、`Ctrl+Shift+8`、`Ctrl+Shift+7` |
| 画面の整理 | 拡張機能の Shadow DOM と、限定したページ用 CSS | Tailwind の Preflight をドキュメント本体へ載せない |

独自 UI は React で、Shadow DOM の中に置きます。Tailwind の CSS はその中だけです。Radix や shadcn/ui は使いません。ポータルが Shadow DOM の外へ出て、Google ドキュメントの画面と混ざるためです。

Google の画面に依存するセレクタは `lib/docs/` に隔離しています。UI のコンポーネントはクラス名を直接知りません。

## 公式仕様と、画面依存の部分

公式に確認した制約です。Nodo はこの範囲に従います。

- タブは 1 文書あたり 100 個まで。[Use document tabs](https://support.google.com/docs/answer/15499791)
- 階層は 3 段まで。同じヘルプの "nest up to 3 tab levels"。
- 最後の 1 タブは削除できない。
- 提案モードではタブの追加、移動、削除ができない。
- 書式ショートカットは [Keyboard shortcuts for Google Docs](https://support.google.com/docs/answer/179738) の Linux 欄。

2026-10-16 に、公開文書の編集画面で確認した非公開の画面構造です。ここが変わると `lib/docs/selectors.ts` と `lib/docs/labels.ts` を直します。

- タブは `.chapter-container`。見出しのアウトライン（`.navigation-item`）とは別です。
- タブメニュー（`.chapter-overflow-menu`）に、サブタブの追加、削除、複製、名前の変更、上に移動、下に移動がある。英語 UI と `hl=ja` の日本語 UI の両方で文言を採取した。
- 入力欄は `iframe.docs-texteventtarget-iframe` の中の `contenteditable`。本文は `canvas.kix-canvas-tile-content` に描かれる。
- キャレット位置は `.kix-cursor-caret` の矩形。段落ごとの DOM は無いので、「＋」はキャレットの行に出します。

ページレスにはしません。背景色の変更は編集領域の周囲だけで、文書設定ではありません。

## 必要なもの

- [Bun](https://bun.sh/) 1.2 以上。このリポジトリのロックファイルは Bun 1.4.3 で管理しています。
- Node.js 22 以上。WXT 0.21 の `engines` が Node.js 22 以上を要求し、`wxt` コマンドの shebang も Node.js です。Vite 8 も Node.js 上で動きます。導入、テスト、スクリプトの起動は Bun に揃えています。
- PC 版 Brave。読み込む成果物は Chromium 向け Manifest V3 です。

確認に使ったバージョンは Node.js v22.14.0、Bun 1.4.3、Brave 1.97.57（Chromium 155.0.8059.80）です。

## セットアップとビルド

```bash
bun install
bun test
bun run typecheck
bun run build
```

`bun install` は `wxt prepare` も実行します。完成版は `dist/chrome-mv3` です。このフォルダだけで動作し、Bun も開発サーバーも要りません。

## Brave への導入

1. `brave://extensions` を開く。
2. デベロッパーモードをオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を選び、`dist/chrome-mv3` を指定する。
4. Google ドキュメントの編集画面（`https://docs.google.com/document/d/...`）を開く。

更新するときは `bun run build` のあと、拡張機能カードの再読み込みを押します。文書タブも再読み込みしてください。

専用プロファイルで起動するスクリプトもあります。既存のプロファイルとは別です。

```bash
bun run build
./scripts/brave.sh
```

引数に URL を足せます。

```bash
./scripts/brave.sh "https://docs.google.com/document/d/あなたの文書ID/edit"
```

## 開発とデバッグ

```bash
bun run dev
```

WXT が Brave を起動します。`wxt.config.ts` の `webExt.binaries.chrome` が `brave-browser` です。開発中の出力も `dist/chrome-mv3` に出ますが、このモードは開発サーバーが動いている必要があります。配布や日常利用には `bun run build` の成果物を使ってください。

デバッグ:

- ポップアップを右クリックして検証する。
- 文書の DevTools で、拡張機能のコンテンツスクリプトを選ぶ。
- `brave://extensions` のサービスワーカーから、`Ctrl+Shift+Period` のコマンドを確認する。
- タブ一覧が空のときは、Google が画面構造を変えた可能性があります。`lib/docs/selectors.ts` を見てください。「元のタブ欄」から標準のタブは操作できます。

Brave Shields は、初期状態のまま拡張機能のコンテンツスクリプトが動くことを確認しています。Shields を切る必要はありません。Cookie も、Google ドキュメント自身が必要とするもの以外は使いません。

## 使い方

1. 文書を開くと、左にページ一覧が出ます。タブをクリックすると、そのタブへ移動します。
2. 「新しいページ」はルートのタブ、「子ページを追加」はサブタブです。3 段目の下には子ページを作れません。
3. ページ名をダブルクリックすると名前を変えられます。`···` から上へ、下へ、複製、削除ができます。削除の前に確認します。
4. 同じ階層の左にあるつまみをドラッグすると、その中で並べ替えます。別の親の中へ入れる操作は、子ページの追加を使ってください。
5. 本文にキャレットがあるとき、ページ左の余白に「＋」が出ます。サイドバーの「現在の段落の書式」からも同じメニューを開けます。選んだ書式は、そのカーソル位置への公式ショートカットです。メニューを開いてもキャレットを動かさないよう、ボタンの押下ではフォーカスを奪いません。
6. 「Googleのメニュー」で File などのメニューと書式ツールバーを戻します。「元のタブ欄」で Google のタブ一覧を表示します。「標準表示」で Nodo を畳みます。ポップアップからも切り替えられます。

本文の入力、日本語 IME、元に戻す、共同編集、コメント、変更履歴は、Google ドキュメントの編集エンジンのままです。Nodo はキー入力を常時フックしません。書式を選んだときだけ、ショートカットを 1 回送ります。変換中の IME がある状態で書式メニューを使うと、変換とぶつかる可能性があります。確定してから選んでください。

タブの削除や移動が、本文の `Ctrl+Z` で戻るかは Google ドキュメント側の動作です。Nodo はそれを置き換えません。

## 権限

- `storage`: 表示のオンオフだけをこのブラウザに保存します。
- `activeTab`: ポップアップが、今のタブが文書かどうかだけを見ます。
- コンテンツスクリプト: `https://docs.google.com/document/d/*` と `https://docs.google.com/document/u/*/d/*` だけ。
- 書式の転送は、そのコンテンツスクリプトへの `tabs.sendMessage` だけです。`tabs` 権限は付けていません。Brave 上で、この権限のまま転送できることを確認しています。

文書の内容を独自のサーバーへ送る処理はありません。ネットワーク権限で Google API を呼んでもいません。

## 検証

### 画面構造（Chrome 154、ログインなしの公開文書）

対象は [Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU/edit) です。編集権限はありません。

- キャンバス、`docs-texteventtarget-iframe`、タブのツリー、タブメニューを確認した。
- 「Hide outline」を拡張機能と同じクリック手順で実行し、アウトラインが閉じた。
- アウトラインの項目をクリックし、URL の `#heading=` が変わった。
- 読み込まれたスクリプトに、編集処理が `isTrusted` を要求する記述は見つからなかった。見つかった `isTrusted` は、操作があったことを記録する処理だった。
- 閲覧専用のため、追加、名前の変更、移動、削除のメニュー項目は無効だった。この環境では、編集可能な複数タブ文書での成否は未確認。

### 拡張機能（Brave 1.97.57、同じ公開文書、Shields は初期設定）

`dist/chrome-mv3` を `--load-extension` で読み込んだ。

- `nodo-ui` の Shadow DOM に、ページ「Trace Event Format」だけが出た。アウトラインの見出しはページになっていない。
- 閲覧モードの案内が出て、「新しいページ」は押せない。
- メニューバーは隠れ、元のタブ欄は透明になる。本文のキャンバスは残る。
- 「現在の段落の書式」から書式メニューが開く。
- 「見出し 1」を選ぶと、入力欄の `contenteditable` で `keydown` を観測した。`key` は `1`、`code` は `Digit1`、`keyCode` と `which` は 49、Ctrl と Alt が有効、Shift は無し。`isTrusted` は false。通知は「見出し 1のショートカットを、編集中の位置へ送りました。」
- 「Googleのメニュー」で File / Edit / View が戻り、「標準表示」で Nodo のサイドバーが畳まれ、復帰用のボタンが残る。
- Tailwind の Preflight は文書のスタイルシートに入っていない。文書へ追加されるのは、カスタムプロパティの `@property` と、`html.nodo-mode` で始まる少数のルールだけ。
- コンソールに Nodo 由来の例外は出ていない。401 は、ログインしていない Google ドキュメント自身のリクエスト。

未検証です。編集できるアカウントがこの環境に無いため、確認済みとは扱いません。

- 選んだ書式が、編集中の段落のスタイルを実際に変えること。ショートカットが編集欄へ届くことは確認した。閲覧専用文書ではスタイルは変わらない。
- 編集可能な文書でのページ追加、名前の変更、複製、削除、上下移動、ドラッグ。
- キャレット横の「＋」。閲覧専用文書ではキャレット矩形が 0 で、余白の「＋」は出なかった。サイドバーの書式ボタンは確認した。
- 変換中の IME、共同編集のカーソル、コメント、変更履歴との同時操作。
